# [TRAINING] fictional rehearse a Fictional Reconciliation local release

## Scenario and user story

As the fictional Fictional Reconciliation release manager, I want to rehearse a local ZIP
release behind a conceptual gate so that the team can practice evidence and
rollback without deploying or publishing anything.

The gate is a training design. It is not installed or enforced by this
scenario pack, and a local ZIP is not deployment evidence.

## Numbered tasks

1. Read the Day 2 Exercise 4 instructions and the independent review notes.
2. Draw or write the conceptual gate: tests, public allow-list check, then a named human release decision.
3. Run the two test suites and the CLI check from the repository root.
4. Rehearse the local archive into an explicit output path; do not upload it, deploy it, or call an external service.
5. Record the artifact path, actual commands, reviewer, and rollback in `lab-notes/release-day-2.md`.
6. If a command fails, preserve the failure as an evidence-based incident note and do not call the release successful.

## Exact files and commands

Files: `training-lab/status.py`, `training-lab/records.json`,
`training-lab/release_rehearsal.py`, and learner `lab-notes/release-day-2.md`
(plus an incident note only if a failure is observed).

From the repository root:

```sh
python3 -m unittest discover -s training-lab/tests/day1 -v
python3 -m unittest discover -s training-lab/tests/day2 -v
python3 training-lab/status.py TX-100
python3 training-lab/release_rehearsal.py --output lab-output/day-2.zip
python3 -m zipfile -l lab-output/day-2.zip
```

The output path is a local learner artifact. This pack does not delete it or
perform cleanup.

## Sample expected result

The rehearsal is expected to list an archive containing only `status.py` and
`records.json` when the command succeeds. A successful command must be
observed before recording that result; no sample is a release claim.

## Acceptance criteria

- [ ] Conceptual gate and its non-enforcement are explicit.
- [ ] Day 1 and Day 2 tests, CLI, and local rehearsal outputs are recorded.
- [ ] A human release manager records the decision and a rollback path.
- [ ] No upload, deployment, remote incident, or production outcome is claimed.

## Evidence required and human role

Evidence: exact command output, archive listing, local path, revision if
known, reviewer, decision, and rollback. The human release manager owns the
release decision; an agent may run the local command but cannot approve it.
