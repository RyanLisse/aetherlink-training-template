# [TRAINING] fictional respond to Northstar metric prompt with new intent

## Scenario and user story

As the fictional Northstar incident scribe, I want to turn a synthetic metric
fixture into a clearly bounded follow-up intent so that the team practices
closing a learning loop without pretending to monitor production.

The metric fixture says 80 errors of 2000 (4%) in the baseline and 160 of 2000
(8%) in the window, compared with a fixed 5% exercise threshold. A breach in
this fixture is a simulated prompt only. It is not a real incident, telemetry,
statistical significance claim, or vendor/customer outcome.

## Numbered tasks

1. Read `data/monitoring.json`, `training-lab/metrics.json`, and the Day 2 Exercise 5 instructions.
2. Run the existing metric checker and capture its exact JSON output.
3. Check that the supplemental counts calculate to the stated 4% and 8%; keep the source labels synthetic.
4. Draft `lab-notes/incident-day-2.md` as a simulated exercise note and `lab-notes/intent-from-metric.md` with outcome, affected users/systems, constraints, open question, and next human gate.
5. Teach back the chain from intent to metric prompt, naming which statements are observed and which remain hypotheses.

## Exact files and commands

Files: `training-lab/check_metrics.py`, `training-lab/metrics.json`,
`scenarios/status-desk/data/monitoring.json`, and learner
`lab-notes/incident-day-2.md` / `lab-notes/intent-from-metric.md`.

From the repository root:

```sh
python3 training-lab/check_metrics.py
python3 -m json.tool scenarios/status-desk/data/monitoring.json >/dev/null
```

## Sample expected result

The source fixture is designed to support this exercise mapping:

```text
baseline: 80/2000 = 4.0%
window: 160/2000 = 8.0%
threshold: 5.0%
breach: true
```

The exact checker output must be captured. It is evidence about a local JSON
fixture only and does not establish a real incident.

## Acceptance criteria

- [ ] Actual checker output is attached to the simulated incident note.
- [ ] Counts and percentages are internally consistent and labelled synthetic.
- [ ] New intent names a measurable outcome, open question, constraints, and human next gate.
- [ ] Teach-back distinguishes observed fixture values from hypotheses and production claims are absent.

## Evidence required and human role

Evidence: checker JSON, monitoring fixture readback, incident note, intent
note, and teach-back reviewer. The human incident scribe records the prompt;
the human product owner accepts or rejects the new intent. Neither role claims
that an external incident system was contacted.
