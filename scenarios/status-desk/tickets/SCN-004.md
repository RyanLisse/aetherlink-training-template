# [TRAINING] fictional add Fictional Reconciliation Day 2 status filter

## Scenario and user story

As the fictional Fictional Reconciliation support lead, I want to filter the supplemental
fixture by a valid status so that a learner can triage a local queue while
returning the same safe two-field shape.

Day 2 starts by reproducing Day 1 evidence. The filter contract is
`filter_status(status, records)`: valid statuses are `pending`, `settled`, and
`failed`; an unknown status such as `cancelled` raises `ValueError`; input
order is preserved and records are not mutated.

## Numbered tasks

1. Read `lab-notes/handoff-day-1.md` and rerun the Day 1 proof before changing code.
2. Implement only `filter_status` in `training-lab/status.py`.
3. Run the Day 2 tests for all valid statuses, no-match behavior, invalid `cancelled`, and the public field allow-list.
4. Run the supplemental five-request check and compare the actual lines with `data/requests.json`.
5. Record any failure mechanism before a bounded correction; preserve unrelated files.
