# Contribution instructions

1. Read [intent.md](intent.md) and [progress.md](progress.md) before changing a training artifact.
2. Verify the current state with the relevant source or command. Do not invent evidence, outcomes, links, or participant results.
3. Keep live notes concise and outcome-focused. Update the relevant recap before extracting a reusable lesson into `knowledge/`.
4. Mark examples and placeholders clearly. Never put secrets or private client information in this repository.
5. Choose the relevant Plan, Design, Build, Test, Deploy, and Maintain phase(s) per session; mark others `NOT IN SCOPE` with a reason. Preserve the order among selected phases. Use a decision record only when changing the shared operating model.
6. Before reporting completion, check every relative Markdown link relative to the containing Markdown file.
